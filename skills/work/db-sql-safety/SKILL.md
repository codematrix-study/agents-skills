# 数据库 / SQL 安全规范

## 1. 修改 SQL 前先检查

不要凭猜测写 SQL，先确认：

- 数据库类型（MySQL 等）及版本相关语法
- 表结构、字段类型、字段默认值、是否允许 NULL
- 主键、唯一索引、普通索引（新增查询条件是否能走索引）
- 外键或应用层的关联关系
- 逻辑删除规则（删除标记字段与取值、查询是否必须带上该条件）
- 分库分表规则（如 `api-service` 使用 ShardingSphere，通用业务表迁移须依据发布记录、目标库 DDL 与 `ShardingConfig` 单独确认）

表结构信息来源优先级：项目内 DDL / Mapper XML / Entity → 项目文档 → 询问用户。仍无法确定字段含义时不要猜。

## 2. 未经用户明确要求，禁止

- 删除数据
- 执行 `DROP`
- 执行 `TRUNCATE`
- 执行大范围 `DELETE`（无 WHERE 或 WHERE 范围不明确）
- 修改生产数据库
- 修改数据库结构

需要执行高风险 SQL 时，必须先把 SQL 和影响范围告诉用户并获得明确确认。

## 3. 迁移 SQL 的交付方式

- 不自行连库执行结构变更；把需要执行的 SQL 写进最终汇报的“需要执行的sql”章节，由用户决定何时、在哪个库执行。
- SQL 要可重复审阅：写明目标库/表，必要时给出回滚语句。
- 加字段注意默认值与历史数据兼容；加唯一索引前提醒检查存量重复数据；大表加索引提醒评估锁表风险。

## 4. 代码层配合

- Mapper 新增/修改查询时，确认参数与占位符一一对应，注意 `${}` 的注入风险。
- 涉及逻辑删除的表，新增查询要带上删除标记条件。
- 批量操作注意数量上限与事务边界。
