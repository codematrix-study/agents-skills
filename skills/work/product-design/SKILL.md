# 产品设计

## 适用范围

面向企业级 Web 产品和管理后台，解决用户如何完成工作任务的问题。仅评估接口、数据库或工程改动范围时，使用 `requirement-analysis`。按用户要求的格式交付，默认在对话中给出设计说明。进入代码实现以用户明确要求为准。

## 设计流程

1. **明确任务。** 梳理用户角色、使用端、触发场景、要完成的工作和成功标准。已有产品先看相邻页面、现有设计规范和业务规则。对会改变流程或权限的未知条件，列出待确认项，先完成已明确的部分。
2. **设计流程。** 从入口走到任务完成，逐步写清谁在什么条件下操作、系统如何响应、业务状态如何变化、用户接下来能做什么。按场景补齐取消、返回、失败恢复和跨角色交接。涉及审批或权限时，按角色和业务状态核对可见内容、可用操作及流转结果。
3. **选择页面和交互。** 按任务、信息量和操作影响选择页面模式，明确入口、信息层级、主操作和返回位置。优先沿用产品已有术语、页面模式和组件，再用 Ant Design 补齐缺口。分别按需查阅[页面模式](references/page-patterns.md)和[交互规则](references/interaction-patterns.md)。
4. **补齐状态和呈现规则。** 写清操作前的条件、进行中的反馈、完成后的结果及恢复方式。区分业务状态与加载、空数据、失败、无权限等界面状态。涉及界面规格、图表、动效或插画时，查阅[全局样式与专题](references/visual-guidelines.md)。

## 评审与交付

用 Ant Design 的四项价值观检查具体场景。依据 [Ant Design 设计价值观](https://ant.design/docs/spec/values-cn/)。

- **自然。** 检查术语和操作顺序是否符合用户的实际工作习惯。
- **确定性。** 检查同一含义和操作在相关页面或终端中的表达是否一致，操作结果是否可预期。
- **意义感。** 检查每一步是否帮助用户推进任务，当前进度、操作结果和下一步是否清楚。
- **生长性。** 检查新手能否发现关键功能、熟练用户能否高效完成高频任务，以及新增同类场景能否复用现有模式。

按需求给出设计目标、适用角色与范围、用户流程、页面结构、关键规则和状态、待确认项。单页或局部调整只展开受影响的内容。评审已有方案时，按对任务完成的影响排序，逐项指出具体位置、受影响的用户及修改建议。
