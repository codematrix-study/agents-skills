# 网站 UI 样式设计(C 端 + 管理端)

目标:产出"专业、协调、可落地"的界面,而不是"信息都在但没有主次"的界面。专业感来自三件事:**层级清晰、规则一致、克制**。不是来自更多装饰。

## 工作流程

按顺序执行,不要跳步。已有项目时,第 2 步优先于一切设计决策。

1. **澄清上下文**(信息已给出就不要再问):页面类型(C 端 / 管理端)、目标用户、核心任务、品牌色/参考风格、技术栈(React/Vue/Tailwind/组件库)。缺失时按"默认假设"推进,并在交付时写明假设。
2. **阅读现有代码与样式**:先找已有的 design tokens、组件库(Ant Design / shadcn / Element 等)、全局样式。**沿用现有体系,不另起炉灶**;只有体系本身混乱时才提议统一。
3. **先定规则,再画页面**:确定 tokens(颜色、字号、间距、圆角、阴影)。模板见 `references/design-tokens.md`。
4. **定页面骨架与层级**:用"5 秒测试"——用户 5 秒内能否回答:这页是干什么的?最重要的信息是什么?下一步点哪里?
5. **补全组件与状态**:每个交互组件都要有 默认 / hover / focus / active / disabled / loading / empty / error。
6. **自检**:对照下方检查清单与对应 reference 末尾的清单。
7. **交付**:代码或方案 + 变更说明(改了什么、为什么、遗留问题)。

## 核心原则(为什么这么做)

**1. 一个页面只有一个视觉焦点。** 当所有元素都在"喊"时,用户什么也看不到。大字号、高饱和色、粗边框、大面积留白都是"音量",预算有限,只给最重要的信息。常见错误:把累计存量(如总积分)做得比每日核心指标更大。

**2. 字号体系只用 4~6 档。** 如 12 / 13 / 14 / 16 / 20 / 28。同一语义永远同一字号。KPI 数字、标题、正文、辅助文字各有固定档位,不要临时造新尺寸。

**3. 一种容器语言。** 要么"卡片 + 细边框",要么"无边框 + 留白分组",全页二选一。混用(有的指标带卡片、有的裸放;有的标题在卡片内、有的在卡片外)是"不协调感"的头号来源。

**4. 颜色有分工。** 品牌色 = 主操作与选中态;红 = 错误/危险;橙/黄 = 警告;绿 = 成功;其余全部灰阶。一个页面同时出现 3 种以上强调色,几乎一定是滥用。链接色不要用在"不可点"的文字上。

**5. 8px 间距体系。** 间距只取 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。相关元素靠近(组内 8~12),无关元素拉开(组间 24~32)——**亲密性**比线条更能分组。

**6. 数字要像数字。** 使用等宽数字(`font-variant-numeric: tabular-nums`)、右对齐、千分位、统一小数位;数字和单位同基线,单位更小更淡;整数与小数不拆分字号。金额、积分、百分比各自约定固定格式并封装成工具函数,全站复用。

**7. 警告要集中,不要复读。** 同一类提示(如"数据未记录")在页面出现不超过 1~2 处;其余用小圆点 + tooltip 降噪。重复的橙色标签会让用户对警告脱敏。

**8. 空状态与加载态是设计的一部分。** 数据为 0 时压缩为一行说明 + 引导,不占整块;加载用骨架屏而非整页转圈;错误给出原因与重试。

**9. 数据口径要诚实。** 图表中"尚未结束的当天/当期"用虚线或"统计中"标注,不要画成断崖;分类之和必须等于总数,差额归入"其他/未归因";X 轴刻度完整均匀。

**10. 可访问性是底线。** 正文对比度 ≥ 4.5:1;可点区域 ≥ 32px(桌面)/ 44px(触屏);焦点环可见;不只靠颜色传达状态(配图标或文字);尊重 `prefers-reduced-motion`。

## 常见反模式速查

| 现象 | 问题 | 修法 |
|---|---|---|
| 小数值(1 人)用超大字号 | 空洞、抢焦点 | KPI 字号统一 28~32,辅助信息降级 |
| 到处是蓝色箭头链接 | 主次操作不分 | 每卡片最多 1 个主链接,其余灰色 |
| 卡片里嵌卡片再嵌卡片 | 层层框线、字号越来越小 | 用分隔线或留白替代内嵌容器 |
| 左右两卡强行等高导致大块空白 | 视觉失衡 | 内容自适应,或补充次级信息 |
| 标签堆叠在数字下方导致行高不一 | 表格节奏被破坏 | 标签挪到同行右侧或用圆点 |
| 渐变 + 阴影 + 描边同时用 | 廉价感 | 三选一,优先细边框 |
| 纯黑 #000 文字 / 纯灰阴影 | 生硬 | 用带色相的深灰(如 #1F2430) |
| 统一的大圆角 + 大阴影 | 模板化 | 圆角 6~12,阴影极轻 |

## 通用自检清单

- [ ] 5 秒内能说出页面焦点与下一步操作
- [ ] 字号 ≤ 6 档,间距全部落在 8px 体系
- [ ] 容器语言一致(卡片/边框/标题位置/圆角统一)
- [ ] 强调色 ≤ 3 种,且各有固定语义
- [ ] 数字右对齐、等宽、格式统一,单位不抢戏
- [ ] 所有交互元素有完整状态;有 empty / loading / error
- [ ] 提示/警告没有重复出现
- [ ] 响应式:≥1280 / 1024 / 768 / 640 断点行为已定义
- [ ] 对比度、焦点环、点击区域达标
- [ ] 没有引入不必要的新依赖

## 实现约定

- 优先使用 CSS 变量承载 tokens,组件只引用变量,不写死色值。
- 沿用项目已有组件库,通过主题变量覆盖样式,而不是到处写 `!important`。
- 暗色模式:若项目已支持,tokens 需同时提供两套;不要只反转颜色,需重新调整灰阶与阴影。
- 默认不添加新依赖;确需引入(如图表库)先说明理由。
- 改样式不改业务:不改接口、数据字段、路由,除非用户明确要求。

## 交付格式

1. **一句话设计思路**(风格方向 + 层级策略)
2. **Tokens 或变更点**(新增/修改的变量)
3. **页面结构说明**(自上而下的区块与理由)
4. **代码或补丁**
5. **变更清单与前后对比**(对应哪条原则)
6. **假设与遗留问题**

## 截图点评模式

用户给截图求点评时:按"层级 → 一致性 → 噪音 → 数据诚实度 → 交互与状态 → 可能的 bug"的顺序列问题;每个问题给出"现象 + 为什么不好 + 具体修法";最后问用户是否需要优化提示词或直接改代码。不要泛泛而谈"可以更简洁"。
