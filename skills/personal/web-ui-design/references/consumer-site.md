# C 端网站设计指南(官网 / 落地页 / 产品站 / 用户中心)

C 端用户是"陌生、注意力短、选择成本低"的访客。设计目标:**3 秒讲清价值、一条清晰转化路径、建立信任、移动端优先**。

## 1. 先定转化目标与风格方向

动手前回答:
- **唯一主转化**是什么?(注册 / 下载 / 咨询 / 购买)全站主 CTA 文案、颜色、位置保持一致。
- **品牌气质**落在哪个坐标?(专业可信 ↔ 活泼亲和;极简克制 ↔ 丰富表现)选定后所有决策服从它。
- **受众与场景**:谁在什么设备、什么心情下看到它?

风格选择要"有观点",避免默认的紫色渐变 + 圆角卡片 + 通用插画。可用的方向:编辑感排版(大字号 + 强留白)、产品截图驱动(真实 UI 做主角)、品牌插画驱动、数据/技术感(等宽字体 + 网格)。选一个方向做到底,不要混搭。

## 2. 页面结构(落地页范式)

自上而下,按需裁剪:

1. 导航(Logo + 3~5 项 + 主 CTA)
2. **Hero**:一句话价值主张 + 副标题 + 主 CTA(+ 次 CTA)+ 产品图/演示
3. 信任条:客户 Logo / 数据 / 媒体
4. 核心价值(3 个以内,每个:图标/图 + 标题 + 一句说明)
5. 功能深入(左右交替图文,每块一个重点)
6. 社会证明:评价、案例、数字
7. 定价(如有)
8. FAQ(消除顾虑)
9. 末尾 CTA(重复主转化)
10. 页脚(链接、法务、联系)

每一屏只讲一件事。区块之间垂直间距 80~120px(桌面)/ 48~64px(移动)。

## 3. 排版与节奏

- 正文 16~18px,行高 1.6~1.75;最大行宽 60~75 个字符(中文约 32~38 字)。
- 标题层级:H1 40~64px、H2 28~40px、H3 20~24px;字重 600~700;标题与正文字号比 ≥ 2:1 才有层次。
- 对齐:大段文字左对齐;居中仅用于 Hero 与短标题。
- 留白即设计:留白不足是"廉价感"的主因。区块内边距 ≥ 64px,卡片内边距 24~32px。
- 同一页面最多 2 种字体(标题 + 正文),中文优先系统字体或 Noto Sans SC,不要为了个性加载多个重字体。
- 视觉节奏:用"密-疏-密"交替(信息密集区后接留白区),并交替背景色(白 / 浅灰 / 品牌浅底)划分区块。

## 4. Hero 区

- 标题讲**用户得到什么**,不讲产品是什么("三分钟完成月度报表" > "智能办公平台")。
- 副标题 1~2 行补充如何实现;主 CTA 文案用动词 + 结果("免费开始使用"),按钮高 48~56px。
- 次 CTA 用描边/文字按钮,明显弱于主 CTA。
- 右侧或下方放**真实产品截图/演示**,优于抽象插画;截图加轻阴影 + 浏览器外框,但不要加倾斜 3D 等过度效果。
- 首屏(1440×800 与 390×844)都要能看到 标题 + CTA。

## 5. 视觉与图像

- 图像风格统一(同一套插画/同一种截图处理/同一色调)。
- 图片:WebP/AVIF、`loading="lazy"`、指定宽高避免布局抖动;首屏图 `fetchpriority="high"`。
- 图标:同一图标库、同一线宽,尺寸 20/24/32 三档。
- 装饰元素(渐变光斑、网格背景)只作背景氛围,透明度低,不与文字竞争;文字区域保证对比度。
- 避免:素材库里的通用商务人物照、与产品无关的 3D 小人。

## 6. 信任与社会证明

- 真实数字优于形容词("12,000+ 团队使用"优于"广受欢迎")。
- 评价带头像、姓名、职位/公司;案例带可量化结果。
- 安全/合规标识、隐私承诺放在转化点附近(注册、支付)。
- 没有真实数据时**不要伪造**,改用"产品能力说明 + 演示"建立信任。

## 7. 定价与表单

定价:
- 2~4 个方案并排,推荐方案视觉突出(描边品牌色 + "推荐"标签),只突出一个。
- 价格数字大(32~48px),周期单位小;功能对比用勾选列表,差异项高亮。
- 月/年切换显示节省比例。

表单:
- 字段越少转化越高;注册先要邮箱/手机号 + 一个动作即可。
- label 在上、输入框高 44~48px、错误即时提示、支持社交/验证码登录。
- 提交按钮宽度跟随表单,文案具体("创建账号"),提交中显示 loading。
- 移动端使用正确的 `inputmode` / `autocomplete` 类型。

## 8. 动效

- 目的:引导视线、确认反馈,不是炫技。入场动效 ≤ 400ms,位移 ≤ 24px,每屏最多一处明显动效。
- 滚动出现(reveal)用 `opacity + translateY`,并尊重 `prefers-reduced-motion`。
- 按钮/卡片 hover:轻微上移 2px 或边框变色,≤ 150ms。
- 不做自动轮播抢占注意力;必须轮播时可暂停且有指示器。

## 9. 响应式与性能

- 移动优先。断点:640 / 768 / 1024 / 1280 / 1536。
- 移动端:单列、触控目标 ≥ 44px、固定底部主 CTA(转化型页面)、导航收为抽屉。
- 容器最大宽度:内容 1120~1280px;文章 ≤ 720px。
- 性能预算:LCP < 2.5s,CLS < 0.1,首屏 JS 尽量 < 150KB(gzip);字体 `font-display: swap`,子集化中文字体或使用系统字体。
- SEO 基础:语义化标签、单一 H1、`<title>` 与 meta description、图片 alt、Open Graph。

## 10. 用户中心 / 账号体系页面

C 端的"后台"不等于管理端,更轻、更友好:
- 密度低于管理端:正文 14~16px、行高更松、卡片更大。
- 首页回答"我的状态是什么、下一步做什么"(套餐余额、待办、快捷入口),而不是堆数据表。
- 设置页:左侧分组导航 + 右侧单列表单;每个设置项 = 标题 + 说明 + 控件。
- 账单/订单:状态标签 + 金额右对齐 + 明确的下载/申请动作。
- 余额/积分/额度类数字:用进度条 + 剩余量表达,而不是孤立大数字;低余额时用警告色并提供充值入口。

## 11. C 端自检清单

- [ ] 3 秒能说清"这是什么、对我有什么用"
- [ ] 全站主 CTA 唯一且一致,首屏可见
- [ ] 每屏只讲一件事,区块间距 ≥ 80px(桌面)
- [ ] 字号层级清晰,中文行宽 32~38 字
- [ ] 图像风格统一,首屏图有性能处理
- [ ] 信任元素真实可信,无伪造数据
- [ ] 移动端首屏、触控目标、表单体验已验证
- [ ] 动效克制并支持减少动态偏好
- [ ] LCP/CLS 达标,SEO 基础齐全
