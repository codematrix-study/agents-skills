# 客户端 UI 样式设计(C 端)

客户端与网站的根本区别:**用户长时间驻留、高频重复操作、期待"像原生一样跟手"**。专业感来自:**平台感、响应感、稳定的信息架构、细节一致**。

## 工作流程

1. **确定平台与形态**:桌面(Electron/Tauri,Win/Mac)、移动(iOS/Android/跨端)、或两者。不同平台的导航、窗口、手势规则不同,先问清楚或按"默认假设"推进并声明。
2. **阅读现有代码**:找已有的主题变量、组件库、布局壳(AppShell)、图标库;沿用,不另起炉灶。
3. **定义产品性格**:工具型(高效、克制)/ 内容型(沉浸、留白)/ 对话型(聚焦输入与输出)。性格决定密度、色彩、动效强度。
4. **先搭"壳"再填"内容"**:导航结构、窗口/页面骨架、全局状态(登录、同步、离线、更新)先于单个页面。
5. **定 tokens**:颜色(亮/暗)、字号、间距、圆角、阴影、动效,见 `references/design-tokens.md`。
6. **逐页设计并补全状态**:默认 / 加载 / 空 / 错误 / 离线 / 权限不足 / 首次使用。
7. **自检与交付**:对照清单;输出变更说明。

## 核心原则(为什么这么做)

**1. 尊重平台习惯。** macOS 用户期待红绿灯窗口按钮、`⌘` 快捷键、半透明侧边栏;Windows 期待标题栏按钮靠右、`Ctrl` 快捷键、Fluent 风格;iOS 期待左滑返回、底部 Tab;Android 期待系统返回、Material 动效。"像原生"= 用户零学习成本。跨平台产品保持**品牌一致、交互遵循各平台**。

**2. 响应感优先于华丽。** 点击反馈 < 100ms;>300ms 的操作要有进度或骨架;乐观更新(先改 UI 再同步)能显著提升"跟手感"。动效服务于因果关系(从哪来、到哪去),不做装饰。

**3. 信息架构稳定。** 导航层级 ≤ 3;主导航位置固定不随页面变化;用户在任意位置都知道"我在哪、怎么回"。频繁使用的功能离手最近。

**4. 密度匹配场景。** 工具型桌面应用可以紧凑(行高 32~36px、正文 13~14px);移动端和内容型必须宽松(正文 15~17px、可点 ≥ 44pt)。同一产品内密度档位固定,不要一屏紧一屏松。

**5. 层级靠"表面"而非"线框"。** 客户端更适合用背景明度差(侧栏 / 主区 / 浮层)区分区域,边框只作辅助。减少线条,界面更轻盈、更像原生。

**6. 颜色克制,主题完整。** 亮/暗两套主题从一开始就设计;跟随系统;强调色只用于主操作、选中、进度。暗色不是反色:需重调灰阶、降低饱和、提亮强调色。

**7. 状态永远可见。** 同步中/已同步、网络断开、登录过期、有更新、后台任务进行中——这些全局状态要有固定位置的轻量指示,而不是弹窗轰炸。

**8. 输入是核心路径。** 对话/搜索/命令输入框始终可达,支持快捷键、粘贴、拖拽、IME 输入法组合(中文输入时回车不误发送)。

**9. 首次体验即产品。** 空状态不是空白:给出一句说明 + 示例 + 主操作。首次启动 ≤ 3 步引导,可跳过。

**10. 可访问性与国际化预留。** 文字缩放(动态字体 / 系统缩放)不破版;对比度 ≥ 4.5:1;不只靠颜色;文案长度预留 +30% 空间;时间、数字、货币本地化。

## 常见反模式

| 现象 | 问题 | 修法 |
|---|---|---|
| 把网页后台原样塞进客户端 | 无平台感、密度失衡 | 重做壳:标题栏、侧栏、快捷键、系统菜单 |
| 到处弹窗确认 | 打断流程 | 用撤销(Undo Toast)代替确认,危险操作才二次确认 |
| 自绘标题栏却失去拖拽/双击最大化 | 反平台 | 保留系统行为,设置 `-webkit-app-region` 正确区域 |
| 列表无骨架、点击无反馈 | 感觉卡顿 | 骨架屏 + 按压态 + 乐观更新 |
| 暗色模式只反转颜色 | 刺眼、层级丢失 | 独立调色,层级靠表面明度 |
| 每页一套布局 | 学习成本高 | 抽取 AppShell + 页面模板 |
| 全屏 loading 遮罩 | 阻塞感强 | 局部 loading,保持可操作 |
| 滚动条、焦点环被全局重置掉 | 可用性下降 | 自定义但保留可见与可拖拽 |

## 通用自检清单

- [ ] 平台规范已遵循(窗口控件、返回手势、快捷键、系统菜单)
- [ ] 全局壳稳定:导航位置固定、全局状态有指示
- [ ] 亮/暗主题齐全,层级用表面明度表达
- [ ] 密度档位统一,可点区域达标(桌面 ≥ 28px,移动 ≥ 44pt)
- [ ] 所有交互有按压/hover/focus 反馈
- [ ] 加载 / 空 / 错误 / 离线 / 首次使用 状态齐全
- [ ] 动效 150~300ms,尊重"减少动态"
- [ ] 输入核心路径顺畅(快捷键、IME、粘贴、拖拽)
- [ ] 文字缩放、长文案、多语言不破版
- [ ] 没有无谓的新依赖,不改业务逻辑

## 实现约定

- 主题用 CSS 变量(桌面/Web 容器)或主题对象(原生/RN/Flutter)集中管理,组件只引用 token。
- 桌面 Electron:区分拖拽区与可点区、处理窗口失焦态(失焦时标题栏/侧栏降低对比)、使用系统字体栈、`color-scheme` 与 `nativeTheme` 同步。
- 移动:处理安全区(safe area)、键盘遮挡、手势冲突、横竖屏、刘海与动态岛。
- 图标统一图标库与线宽;尺寸 16/20/24。
- 不改接口与数据结构,除非用户明确要求。

## 交付格式

1. 设计思路(产品性格 + 平台策略,一两句)
2. Tokens(亮/暗)
3. 壳与导航结构说明
4. 关键页面规范或代码
5. 状态清单(各页面的 空/加载/错误/离线)
6. 变更清单与遗留问题

## 截图点评模式

按"平台感 → 信息架构 → 层级与密度 → 一致性 → 状态与反馈 → 可访问性"顺序列问题;每条给"现象 + 原因 + 修法";结尾询问是否生成优化提示词或直接改代码。
